01The problem

Print products are deceptively complicated commerce. A single business card isn't one SKU — it's a matrix of sizes, stocks, finishes, quantities, and turnaround options, each combination with its own price. Off-the-shelf store platforms handle simple variants; they fall over when the catalogue is large and every product is a configurator.

PrintMe exists to handle that reality properly: customers configure exactly what they need, prices are always correct, and the order that reaches production carries everything the print workflow needs.

02What I built

Configurable product system

Products are defined by option schemas rather than flat variants, so a large catalogue stays manageable and consistent.

Server-side pricing & validation

Every configuration and price is validated on the server with Zod schemas — the client can never invent a price.

Checkout with Square

A payment workflow built on Square, from cart through confirmation, designed around real order data.

Admin system

Catalogue management, order visibility, and the operational controls a print business needs without touching code.

Search & discovery

Catalogue search and structured navigation so customers find the right product before they configure it.

SEO & performance groundwork

Per-page metadata, clean URLs, and server rendering so the catalogue is discoverable and fast.

03How it's built

The platform is a Next.js and TypeScript application backed by Supabase and PostgreSQL. The data model treats product options as first-class schema, and the same validation source of truth (Zod) runs on both sides of the wire.

  1. Catalogue & configurationCustomer browses the catalogue and configures a product — options driven by schema, not hardcoded forms.
  2. Server validation & pricingThe chosen configuration is validated and priced server-side against the product's option schema.
  3. CheckoutSquare processes payment; the order is written with its full configuration snapshot.
  4. Admin & productionOrders surface in the admin system with everything production needs to run the job.

04Status & what's next

PrintMe is in active development, working toward production launch. The current build is available in the interactive preview above while work continues on hardening checkout, expanding the admin system, and preparing the catalogue for real production volume.

05What I learned

Commerce correctness lives on the server. Designing the option schema first — before any UI — made pricing, validation, and admin tooling fall out of one source of truth instead of three copies that drift apart. It also made testing meaningful: the tests exercise the same schemas the customer hits.
